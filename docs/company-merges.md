# 회사·기관 통합 및 검증

## 2026-09-28 운영 적용

`20260927020000_company_merges.sql` 및 검증된 HIRA 5쌍의 연결을 같은 트랜잭션으로 적용했다. 운영 스키마 확인 → 전체 롤백 검증 → 적용 순서로 실행했고 `MERGE_DEPLOYMENT_APPLIED`를 확인했다. 적용 직전 회사 리뷰는 0건이었다.

2026-09-27 공식 병원정보 API에서 기존/새 식별자 모두 조회되고 기관명·시군구뿐 아니라 전체 주소·전화·개설일·기관종류가 일치한 쌍:

- 김훈정신건강의학과의원
- 에이치엘의원
- 지리산한방병원
- 유니한의원
- 플러스마이너스한의원

기존 공개 항목을 대표로 유지하고 새 비공개 항목에서 대표로 연결한다. 회사 행과 원천 식별자·분류는 삭제하지 않으며, 기존 slug와 리뷰 연결도 유지한다. 전체 79,894행/공개 79,886행은 변하지 않는다. 비공개 8행 중 5행은 통합 주소, 3행은 미확정 후보다.

새솔어린이병원·해바라기치과의원·수한의원은 이전 식별자가 현재 API에 없어 원래의 상세 정보와 비교할 수 없었다. 이름·지역만으로 합치지 않고 비공개 후보로 남겼다. 과거 원천 또는 공식 식별자 변경 근거가 확보되면 재검토한다.

증거는 `artifacts/companies/hira-duplicate-evidence-2026-09-27.json`, 대상 계획은 `verified-merge-plan.json`, 적용 SQL은 `verified-merges-apply-rls.sql`에 보관한다. 원문 연락처·주소·암호화 원천 식별자는 저장하지 않고 일치 여부와 해시 식별자만 보관했다.

## 정책과 보존 범위

- `company_merges`: RLS 활성화, anon/authenticated/service_role 원시 접근 권한 없음. 공개 SELECT 정책도 없음.
- `merge_companies`: authenticated 실행 가능하지만 DB에서 `require_admin_aal2()`로 관리자 + MFA를 강제한다. 증거 URL과 설명이 필요하다.
- 리뷰는 ID·내용·승인·열람 만료일을 유지하고 company_id만 대표 기관으로 옮긴다. 동일 작성자의 양쪽 리뷰가 있거나 원본 순위 자료가 있으면 자동 통합을 거절한다. 연결 순환 및 다단계 통합도 거절한다.
- 원천 분류는 원본 행에 남으며 대표 기관의 정보를 임의로 덮어쓰지 않는다. 후속 수집도 원천 행을 누적 기준에 보존한다.
- `resolve_company_slug`: anon/authenticated에 공개된 목적지 slug 하나만 반환한다. 관리자 근거·리뷰 작성자·비공개 목적지는 노출하지 않는다.
- 상세 화면은 통합 주소를 대표 주소로 이동시킨다. URL 값은 slug 형식을 검증해 내부 경로만 사용한다.
- 이번 5쌍의 데이터 반영은 리뷰/순위가 없는 비공개 원본에 한정한 DB 소유자 데이터 migration이다. 사용자 JWT 또는 MFA 상태를 위조하지 않았다. 일반 관리자 경로에는 위 RPC의 MFA 검사가 적용된다.

## 확인 결과

- 격리 DB: anon·사용자 A/B·MFA 없는 관리자 통합 차단, MFA 관리자 통합 성공, 리뷰 보존, 중복 리뷰 충돌 중단, 잘못된 증거 원자적 롤백 검증.
- 전체 테스트 272개, production build/TypeScript 통과. lint 오류 0개, 기존 img 경고 3개. 임시 테이블 RLS 추가 후 영향 범위 테스트 8개 재검증 통과.
- 운영 공개 API: 5쌍 대표 주소 반환, 미확정 3쌍은 null 유지, 원시 통합 감사정보 조회와 익명 통합 호출은 42501로 차단.
- 초기에 자동 승인 검토가 Run without RLS 클릭을 차단했다. 실행을 취소하고 임시 테이블에도 RLS를 명시해 다시 검증했다. 보안 경고를 우회하지 않고 정상 Run으로 적용했다.

주간 자동 갱신은 `docs/hospital-recurring-runbook.md` 참조. PC/Codex 앱과 DB 정상 접속에 의존하는 로컬 예약이며 서버 상시 크론은 아니다.
