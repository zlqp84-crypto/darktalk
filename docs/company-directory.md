# 회사·기관 디렉터리 1단계

## 범위와 현재 상태

2026-09-18 운영 DB의 information_schema.columns를 조회했다. public에는 comments,
likes, posts, profiles가 있었고 기업/리뷰 테이블은 없었다. 기존 migration 두 개도 확인했다.
기존 테이블은 수정하지 않고 `20260918030000_company_directory.sql`로 세 테이블과 검색 RPC를 추가했다.
운영 적용은 SQL Editor에서 수행했다. CLI migration 이력 등록은 하지 않았다.
앱 운영 배포: `dpl_9ZHDVSMRLdotzujHrVWJ7njSa5K2`, https://darktalk.vercel.app/company.

기존 기업 목록 8개의 임의 평점·연봉·리뷰 수, 모든 기업에 공통으로 표시되던 가짜 리뷰와
직급별 연봉을 제거했다. 실제 데이터가 없으면 준비 중/검색 결과 없음으로 표시한다.
회사 상세·출처·분류 검색·페이지 이동은 DB를 조회한다. 리뷰 작성 링크가 가짜 기업 상세로
열리던 `/company/write`는 준비 안내 페이지로 교체했다. 과거 영문 회사 URL은 회사명 검색으로 연결한다.

실제 회사 목록의 대량 등록은 OpenDART 인증키 또는 공식 CORPCODE.xml/ZIP 파일이 준비되어야 한다.
현재 기업 데이터는 0건이며, 수집·등록을 완료했다고 주장하지 않는다.
리뷰 작성/승인, 열람권, 회사 추가 요청 접수, 관리자 편집 UI는 다음 단계다.

## 데이터 구조

| 테이블 | 내용 |
|---|---|
| companies | 회사·기관 ID, 이름, 안정적인 slug, 원천 시스템/고유번호, 출처 URL, 원천 변경일, 확인일, 홈페이지, 공개 여부 |
| company_classifications | 유형·태그·업종·지역과 각 항목의 근거 URL/기준일 |
| company_rankings | 국내 1,000대 기업 순위, 기준연도, 순위, 산정 기준, 발행기관, 근거 URL/기준일 |

유형: 대기업, 중견기업, 중소기업, 공기업, 공공기관, 공무원·행정기관, 기타 기관.
공무원은 사람 단위가 아닌 소속 행정기관을 등록한다. 유형은 회사당 1개다.
태그: 스타트업, 외국계, 상장기업. 유형과 독립적이며 복수 등록 가능하다.
국내 1,000대 기업은 유형/태그가 아닌 출처·기준연도가 있는 순위 자료다.
확인되지 않은 유형은 행을 만들지 않으며 UI는 분류 확인 중으로 표시한다.
상장기업이라는 이유만으로 대기업/중견기업으로 분류하지 않는다.

출처 간 같은 회사 매칭은 법인 단위로 확인한 뒤 처리해야 한다. 회사명만으로 자동 병합하지 않는다.
사업장/지점 자료를 들여오는 경우 법인과 사업장의 단위를 먼저 정해야 한다.
현재는 같은 원천의 고유번호 중복만 DB에서 강제 차단한다.

## 공개 권한

- 세 테이블 모두 RLS 사용. anon/authenticated는 SELECT만 허용한다.
- companies는 is_published=true만 조회할 수 있다. 신규 기본값은 false다.
- 분류/순위는 연결된 회사가 공개된 경우에만 조회된다.
- 일반 사용자와 관리자 브라우저 모두 직접 INSERT/UPDATE/DELETE 불가.
- 적재는 신뢰된 DB 소유자/service_role 경로만 사용한다. 서비스 키를 브라우저에 넣지 않는다.
- search_companies는 SECURITY INVOKER여서 RLS를 유지한다. 검색어는 100자까지이며
  SQL 문자열 검색의 %, _, 역슬래시를 리터럴로 처리한다. 응답은 최대 25개다.
- 화면은 24개를 표시하고 25번째 행으로 다음 페이지 여부를 판단한다. 회사명/id로 정렬한다.
- 검색은 부분 회사명, 정확한 유형/태그/업종/지역, 순위 기준연도를 조합한다.
  페이지 사이에 원천 데이터가 바뀌면 offset 페이지가 이동할 수 있다.
- 이름 정렬과 분류/순위 필터 인덱스를 추가했다. 전체 목록을 브라우저로 내려받지 않는다.
  대량 적재 후 부분 검색 실행계획/응답시간을 측정하고 필요하면 trigram 인덱스를 추가한다.

## DART 수집

공식 명세: https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018

고유번호 ZIP에 포함된 corp_code, corp_name, stock_code, modify_date만 사용한다.
개인 이름, 연락처, 사업자등록번호 등은 수집하지 않는다. 전체 목록은 기본정보이므로
홈페이지/업종/지역/기업 규모/연봉을 추측해 채우지 않는다.

`OPENDART_API_KEY`를 로컬 `.env.local` 또는 실행 환경에 지정한다. NEXT_PUBLIC_ 접두사는 사용하지 않는다.
키는 로그와 생성 SQL에 기록하지 않는다. API 다운로드는 공식 호스트로만 하며 리다이렉트를 거부한다.

```sh
# 공식 API → 검토용 SQL. 운영 DB에 자동으로 실행하지 않는다.
npm run companies:prepare

# 공식적으로 내려받은 파일로도 준비 가능. 확인일은 실제 취득 날짜다.
npm run companies:prepare -- --input CORPCODE.xml --checked-on 2026-09-18

# 검토 후 신규 레코드를 공개하는 SQL 생성 (기존 비공개 행을 재공개하지 않음)
npm run companies:prepare -- --publish --output artifacts/companies/dart-published.sql
```

출력은 기본적으로 `artifacts/companies/dart-import.sql`. 원본 데이터와 출력 SQL은 Git/배포에서 제외한다.
기존 출력 파일을 덮어쓰지 않는다. 재실행 시 다른 출력명을 지정하거나 기존 결과를 검토 후 정리한다.
XML/ZIP 크기, DTD, 형식, 중복 ID, 유효 날짜를 검사하며 API 오류/비정상 파일은 적재 SQL을 만들지 않는다.

신규 회사는 기본 비공개다. 같은 고유번호는 UPSERT하고, 더 오래된 자료는 이름/상장 태그를 되돌리지 않는다.
재수집은 기존 공개 여부, 수동 분류, 홈페이지, slug를 보존한다. 기업 전체 삭제는 하지 않는다.
출처 목록에서 없어진 회사의 폐업 여부를 추측하지 않는다. 상장 태그는 이 수집기의 근거로 만든 항목만 갱신한다.
`--publish`는 신규 공개 레코드를 만드는 명시적 옵션이며 자료를 검토한 후 사용한다.
SQL 실행 전 대상 프로젝트/원천 건수/기준일/공개 여부를 확인한다.

다음 데이터 출처 후보: ALIO 공공기관, 공식 행정기관 목록, 중견/대기업 분류 자료.
각각 이용 조건·고유번호·분류 정의를 확인한 후 별도 어댑터를 만든다. 타사이트 리뷰 각색 수집은 하지 않는다.

## 검증

- 기존 P0 168개 + 회사 디렉터리/수집 28개 = 196개 테스트 통과.
- 테스트: 공개/비공개 RLS, 클라이언트 쓰기 차단, 복합 검색, literal wildcard,
  순위 연도, 단일 유형, 출처 필수, 25개 제한/페이지 경계, URL 스킴 검사.
- 수집 테스트: 실제 ZIP 구조 fixture, 선행 0 유지, XML 엔티티, DTD/잘못된 날짜/API 오류 거부,
  따옴표/역슬래시 이름, 중복 수집, 비공개 유지, 수동 분류 보존, 오래된 스냅샷 차단.
- TypeScript/production build 통과. ESLint 오류 0, 기존 img 경고 3개.
- 운영 익명 PostgREST: 검색 RPC + 분류/순위 관계 조회, 회사 상세 조회 모두 HTTP 200.
  운영 회사 레코드가 없으므로 응답은 빈 목록이다. 실제 대량 데이터 성능은 아직 미검증이다.
- 운영 브라우저에서 준비 안내, 공무원·행정기관 분류 검색, 필터 초기화 확인.
  수집된 error/warn 로그 없음. 레코드가 있는 목록/상세 화면의 운영 E2E는 실제 적재 후 확인한다.

다음 리뷰 단계에서는 별도의 작성자 연결 정보/비공개 본문/공개 집계/열람권 구조를 설계하고
리뷰 승인 후 기간제 열람권을 DB에서 검증해야 한다. 현재 테이블에는 리뷰 본문이나 회원 ID가 없다.
