# 병원 주간 갱신 실행 절차

범위: HIRA 병원 목록. DART·ALIO·MME 정기화는 이 예약에 포함하지 않는다. 로컬 Codex 예약이므로 PC와 앱이 켜져 있고 프로젝트·인증키·운영 DB 관리 화면 접속이 가능해야 한다. 서버 상시 실행 크론이 아니다.

## 매주 실행

2026-09-28 공개 범위 변경: HIRA 종별 `01`(상급종합), `11`(종합병원)만 신규 공개한다. 전체 원천 스냅샷과 누적 기준은 유지하며 나머지 기관은 비공개로 보존한다. 기존 비공개·통합 원천 행은 자동 재공개하지 않는다. 공개 기관이 다른 종별로 변경되면 갱신 SQL에서 비공개로 전환한다. 이것은 병상 수 기준이 아니라 공식 기관 종별 기준이다.

1. 저장소 상태와 이 문서, `docs/company-expansion.md`를 읽는다. 비밀값이나 인증 헤더를 출력하지 않는다. 마지막 `hira-catalogue-baseline-YYYY-MM-DD.json`이 `applicationVerified:true`인지 확인한다. 원천 스냅샷과 누적 기준을 혼동하지 않는다.
2. `node --env-file=.env.hira.local scripts/companies/collect-hospitals.mjs`를 실행한다. 같은 날짜의 완전한 스냅샷이 있으면 재사용한다. 수집 실패·중복 ID·총건수 변화가 발생하면 부분 자료를 적용하지 않는다.
3. `node scripts/companies/prepare-hospital-cycle.mjs --snapshot artifacts/companies/hira-YYYY-MM-DD.json --output artifacts/companies/hira-cycle-YYYYMMDD-RUN`으로 새 실행 묶음을 만든다. 출력 폴더를 재사용하지 않는다. 큰 변화(추가+변경 또는 누락이 기준의 2% 초과, 최소 허용 100건)는 자동 중단된다.
4. 보고서의 추가·변경·누락을 검토한다. 신규 중복 후보는 비공개다. 누락은 폐업이나 삭제로 처리하지 않는다. 추가·변경이 0이고 새로 확인할 문제가 없으면 DB를 쓰지 않고 조용히 종료한다.
5. 운영의 companies/classifications 구조와 최신 상태를 확인한 후 `preflight.sql`을 SQL Editor의 정상 인증된 연결로 실행한다. `HOSPITAL_REFRESH_PREFLIGHT_OK` 성공을 확인한다. 임시 테이블에도 RLS를 명시하며 기존 공개 테이블 RLS는 변경하지 않는다. RLS 미설정 경고가 나타나면 우회하지 말고 SQL의 RLS 설정을 확인한 후 재검증한다.
6. 검증된 동일 묶음의 `apply.sql`을 실행한다. `HOSPITAL_REFRESH_APPLIED`가 없으면 적용 완료를 주장하지 않는다. 오류 발생 시 무작정 재실행하거나 기준 해시를 바꾸지 말고 현재 DB 상태를 재조회한다. 실제 운영 값과 기준이 다르면 수동 검토가 필요하다.
7. 공개 API에서 신규 공개·명칭 변경 결과와 중복 후보 비노출을 확인한다. SQL 안의 전체 이름 해시와 변경 분류 해시 검사도 통과해야 한다. 기존 slug·리뷰 참조를 보존하고, 공개 여부는 범위 밖 종별을 숨기는 경우에만 변경한다.
8. 모두 성공한 경우에만 `next-baseline.json`의 `applicationVerified`를 true로 하여 새 `hira-catalogue-baseline-YYYY-MM-DD.json`으로 보관하고 실행 결과에 적용 날짜·건수·검증을 기록한다. 새 기준 파일이 이미 있으면 덮어쓰지 않고 이전 실행 상태부터 확인한다. 다음 실행에 사용할 기준을 실패한 실행에서 만들지 않는다.

## 통합 및 알림

- `company_merges`가 적용된 경우 통합된 원천 행도 누적 기준에 보존한다. 원천 행을 삭제하거나 다시 공개하지 않는다. 범위 밖 종별은 숨기되 기존 비공개 상태는 유지한다.
- 동일 명칭·지역은 중복 후보를 찾는 신호일 뿐이다. 공식 자료에서 주소·전화·개설일·종류까지 일치하는지 확인하고 근거를 남긴다. 증거가 부족하면 자동 통합하지 않는다.
- 관리자 통합 RPC는 admin + aal2를 요구한다. 작성자가 양쪽에 리뷰를 갖거나 순위 자료가 있는 경우에는 자동 통합을 거부한다. 인증 상태를 위조하거나 API 인증키/세션을 추출해서 우회하지 않는다.
- 브라우저 세션 만료·도구 연결 실패·API 오류·검증 실패 시 적용을 중단하고 필요한 조치만 알린다. 변화가 없거나 이미 보고한 미해결 상태가 그대로면 반복 알림을 보내지 않는다. 변경 적용 완료, 새로운 중복 후보, 오류 또는 사용자 조치가 있을 때만 알린다.
