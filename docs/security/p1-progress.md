# 후속 보안·운영 작업

2026-09-27: 1단계 및 신고·탈퇴 접수 SQL 5개 운영 적용 완료. 코드 배포 확인은 아래 후속 기록으로 구분한다.

## 순서와 범위

1. 보안·개인정보: 추천·조회·댓글 카운터, 누락 프로필, 이미지 메타데이터.
2. 신고·탈퇴: 실제 접수 및 데이터 삭제 흐름. 실계정 리뷰 E2E는 보류.
3. 운영: 오류 로그, 알림, 백업/복구, migration 이력 대조.
4. 데이터: 갱신, 검증된 식별자 기반 중복 처리, 행정기관 자료.

## 1단계 현재 변경

- 운영 읽기 전용 재조사: likes는 id/post_id/user_id/created_at, UNIQUE(post_id,user_id), posts CASCADE 및 profiles FK. 0행, NULL/중복 0건. INSERT 정책 1개.
- auth.users의 id/raw_user_meta_data/email_confirmed_at/deleted_at 컬럼 존재 확인. 프로필 없는 계정 2개. Auth 및 기존 콘텐츠 사용자 트리거 없음.
- ensure_my_profile: 이메일 확인이 끝난 본인만 누락 프로필 생성. 닉네임 충돌은 임의 별칭으로 해결. metadata의 관리자/인증 플래그 무시. 기존 프로필을 덮어쓰지 않음.
- 추천: 기존 likes 사용, raw 테이블 클라이언트 접근 금지. 잠금과 UNIQUE로 중복 요청을 멱등 처리. 임의 증감량 차단, 기존 누적 수는 유지하고 실제 신규 반응만 증감.
- 댓글 수: 생성·삭제·이동 DB 트리거로 유지. 구형 증감 RPC는 호환용 no-op. 최초 적용 때 실제 댓글 수와 일치시킴.
- 조회수: 로그인한 이메일 확인 계정만 게시물별 24시간 1회 증가하는 초안. anon 열람은 유지하되 카운트는 증가하지 않음. IP/지문 없음. 비공개 post_view_receipts는 계정/게시글별 마지막 집계 시각 1개를 저장하며, 계정/글 삭제 시 CASCADE. 사용자 선호 질문 답변에 따라 조정 가능.
- 이미지: 일반 업로드 흐름에서 JPEG/PNG/WebP를 브라우저 재인코딩, GIF는 애니메이션 보존하며 메타데이터 확장 제거. 변환 실패 시 원본 업로드하지 않음. **클라이언트 처리이므로 Storage API 직접 업로드에 대한 서버 강제는 아님. 기존 공개 파일 소급 정제도 미수행.**
- 공개 본문에 사람이 직접 적은 개인정보나 사진 자체의 개인정보는 자동 제거하지 않음.

## 검증

- 격리 PostgreSQL 권한/회귀/데이터 테스트 총 254개 통과.
- 로컬 실제 브라우저: EXIF 포함 JPEG → EXIF/XMP/IPTC 없음, 32×16 해상도 유지 확인.
- production build/TypeScript 통과.
- ESLint 오류 0, 기존 이미지 경고 3개. 수집 artifacts는 lint 대상에서 제외.
- 운영 SQL에서 전체 변경을 먼저 ROLLBACK하고 권한 검사 통과(P1_ROLLBACK_PREFLIGHT_OK), 이후 단일 트랜잭션 COMMIT(P1_APPLIED) 확인.

## 신고·계정 관리

- 게시글·댓글·리뷰 신고 접수, 계정당 하루 10개, 동일 대상 중복 접수 방지. DB가 본인 ID를 지정하며 원본 테이블 직접 접근 차단.
- 관리자 OTP 확인 후 신고 원문 조회·처리 상태 변경. 신고자 ID는 관리자 응답에서도 제외. 처리 완료 버튼은 콘텐츠 자동 삭제가 아니다.
- 마이페이지 목업을 본인 프로필 조회·수정으로 교체. 가짜 이메일/가입일/활동량/작동하지 않는 설정 버튼 제거.
- 탈퇴 요청 접수·본인 상태 조회·처리 전 취소·관리자 OTP 목록 조회 구현. 관리자 계정의 탈퇴 요청은 차단.
- **실제 Auth 계정·작성 콘텐츠·Storage 객체 삭제 실행기는 아직 미구현. 접수는 탈퇴 완료가 아니다.** 삭제 범위 질문은 답변 대기이며 운영 계정으로 테스트 요청/삭제를 하지 않았다.
- 서버 오류 이벤트는 고정 코드와 오류 종류만 기록. 원본 예외/요청 URL/헤더/본문/계정 ID는 이 이벤트에 포함하지 않는다. 플랫폼 자체 로그 전체를 제어하는 기능은 아니다.

## 이어서 확인할 사항

- 실제 탈퇴 실행과 서버 강제 이미지 정제에는 서버 전용 Storage/Auth 관리 경로가 필요. 현재 로컬 환경은 공개 anon key만 있으며 service_role 키는 없다. 채팅으로 키를 받지 않는다.
- 오류 알림, 백업 복구 리허설, CLI migration 이력 대조·등록, 데이터 자동 갱신·중복 통합·행정기관 자료는 미완료.
- 2026-09-27 운영 migration 이력 테이블은 여전히 없음. CLI db push를 바로 실행하면 안 된다.
